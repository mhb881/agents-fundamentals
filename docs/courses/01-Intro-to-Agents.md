# 智能体（Agent）入门

## 概述

本节课程将带你认识 **AI 智能体（AI Agent）**——它们是什么、为何重要，以及它们擅长与不擅长的场景。此外，我们还将动手搭建第一个基础智能体。

## 什么是智能体？

每个人对智能体都有不同的定义，我的定义是：

**智能体是一个能够在循环中持续执行动作，直到完成任务的大语言模型（Large Language Model，LLM）。**

就是这么简单。它包含三个核心要素：

1. **LLM**：具备推理和决策能力的语言模型。
2. **动作（Actions）**：实际执行操作的能力（如调用工具、写入文件、发起 API 调用等）。
3. **循环（Loop）**：持续运转直至任务完成，而非只返回一次响应。

聊天机器人（chatbot）只回复一次，而智能体会持续工作。

### 你可能听过的其他定义

* **“配备了工具的 LLM”**——过于简单。仅仅拥有工具并不足以构成智能体。
* **“能够自主达成目标的 AI”**——过于宽泛。究竟什么才算“自主”？
* **“能够规划并执行的 AI”**——比较接近了，但简单的智能体并不一定需要规划能力。
* **“由 LLM 控制执行流程的系统”**——这个定义很准确，核心在于由 LLM 决定下一步该做什么。

这些定义的共同点在于：**LLM 处于主导地位（in the driver's seat）**，由它来决定采取什么行动以及何时停止。

## 为什么需要智能体？

单纯的 LLM 存在以下局限：

* 知识局限于训练数据（信息过时且不完整）
* 仅支持单轮响应（缺乏状态持久性）
* 只能生成文本（无法对现实世界产生实际影响）

而智能体能够：

* 获取实时数据（通过 API、数据库、互联网）
* 逐步拆解并处理多步骤复杂问题
* 真正“动手做事”（创建文件、发送邮件、部署代码）
* 从错误中恢复，并尝试不同的解决路径

两者的本质区别在于**自主行动能力（agency）**——不仅能描述世界，更能作用于世界。

## 智能体擅长什么？

1. **重复性知识工作**：信息检索、内容摘要、数据录入。
2. **代码生成与修改**：编写代码、调试（debug）、重构。
3. **多步骤工作流**：需要按顺序组合调用多个工具的任务。
4. **探索性任务**：例如“在这个代码库（codebase）中找出所有的 X，然后执行 Y”。
5. **辅助性任务**：提升人类工作效率，而非取代人类。

## 智能体不擅长什么？

1. **需要物理实体参与的任务**：这一点显而易见。
2. **缺乏人工监督的高风险决策**：不要让智能体去审批贷款或解雇员工。
3. **依赖人类审美品味的创意工作**：智能体可以起草初稿，但最终拍板的应该是人。
4. **成功标准模糊的任务**：比如只说一句“把这个改得更好”，却没有任何具体要求。
5. **实时性或对延迟敏感的操作**：LLM 的调用耗时较长。
6. **需要真正逻辑推理的任务**：LLM 的**本质是模式匹配而非真正的推理**，面对复杂逻辑往往会失效。

智能体最危险的失效模式是：**一本正经地把事情做错**——因为它们并不知道自己不知道什么。

## 智能体循环

每个智能体都遵循相同的基本运行模式：

```
1. 接收任务
2. 思考下一步该做什么
3. 执行动作（或直接回复）
4. 观察执行结果
5. 若任务尚未完成，返回第 2 步
```

这种模式通常被称为 **ReAct 模式（Reason + Act，推理与行动）**：模型先推理该做什么，接着采取行动，然后再基于观察到的结果进行新一轮推理。

## 智能体的未来趋势

未来的演进方向包括：

* **更强的工具使用能力**：模型在准确选择和调用工具方面的表现正大幅提升。
* **更长的上下文（context）**：更大的记忆容量意味着能够处理更复杂的任务。
* **多智能体系统（Multi-agent systems）**：多个智能体之间相互协同配合。
* **垂直领域专用智能体**：针对特定领域（如编程、科研等）进行微调的智能体。
* **更完善的安全护栏（guardrails）**：让智能体更加安全可控，清楚自身的能力边界。

发展趋势非常明确：智能体将在更少人工干预的情况下处理越来越复杂的任务。但我们尚未达到那个阶段——**当下的智能体仍然需要人类监督**。

## 代码

### src/agent/run.ts

创建基础的智能体运行器（runner）：

```typescript
import { generateText, type ModelMessage } from "ai";
import { openai } from "@ai-sdk/openai";

import { SYSTEM_PROMPT } from "./system/prompt.ts";

import type { AgentCallbacks } from "../types.ts";

const MODEL_NAME = "gpt-5-mini";

export async function runAgent(
  userMessage: string,
  conversationHistory: ModelMessage[],
  callbacks: AgentCallbacks,
): Promise<any> {
  const { text } = await generateText({
    model: openai(MODEL_NAME),
    prompt: userMessage,
    system: SYSTEM_PROMPT,
  });

  console.log(text);
}
```

这是最简化的“智能体”——本质上只是一次普通的 LLM 调用。它还算不上真正的智能体，原因如下：

* **没有工具**（无法执行动作）
* **没有循环**（回复一次即停止）
* **没有记忆**（未使用对话历史记录）

我们将在后续课程中逐步加入这些能力。

### 关于代码的 `callbacks` 参数

简而言之：**它是 Agent 底层逻辑（`run.ts`）与外部界面交互层（`App.tsx`）之间的“事件通信桥梁”**。

`run.ts` 只关注 Agent 的认知与执行流程（调用模型、解析工具、递归循环），不直接依赖具体的界面代码。通过 `callbacks`，它可以在运行过程中把状态**事件驱动**地通知给上层 UI。

#### 1. `AgentCallbacks` 接口定义

在 [src/types.ts](file:///d:/WorkSpace/大师课/ai-courses/作者-Scott-Moss/agents-v2/src/types.ts#L1-L8) 中，它的完整定义如下：

```typescript
export interface AgentCallbacks {
  onToken: (token: string) => void;
  onToolCallStart: (name: string, args: unknown) => void;
  onToolCallEnd: (name: string, result: string) => void;
  onComplete: (response: string) => void;
  onToolApproval: (name: string, args: unknown) => Promise<boolean>;
  onTokenUsage?: (usage: TokenUsageInfo) => void;
}
```

---

#### 2. 各回调函数的具体作用与 UI 对应关系

在 [src/ui/App.tsx](file:///d:/WorkSpace/大师课/ai-courses/作者-Scott-Moss/agents-v2/src/ui/App.tsx#L46-L88) 中，UI 就是通过传入这一组回调来实现终端交互的：

| 回调函数                      | 触发时机                                | 在终端 UI 中的具体作用                                       |
| :---------------------------- | :-------------------------------------- | :----------------------------------------------------------- |
| `onToken(token)`              | 模型流式生成文本中的每一个字符/分块     | 实时拼接文本，在终端实现**打字机流式输出**效果。             |
| `onToolCallStart(name, args)` | 模型决定调用某个工具时                  | 终端立即弹出对应工具卡片，展示入参，并显示正在执行的 **Spinner 加载动画**（状态为 `pending`）。 |
| `onToolCallEnd(name, result)` | 本地执行工具完毕并拿到返回值时          | 将该工具卡片状态更新为 `complete`，并展示执行结果。          |
| `onToolApproval(name, args)`  | **调用敏感工具前（如 Shell 命令）**     | **触发人机协同（HITL）**：暂停代码执行并返回一个 `Promise<boolean>`，终端弹出 `[Yes / No]` 审批弹窗，用户回车确认后才会继续执行。 |
| `onTokenUsage(usage)`         | 统计完本轮对话消耗的 Token 时           | 驱动终端底部的 **Token 水位计（TokenUsage 组件）**，显示当前上下文占比（如 `18.5%`）。 |
| `onComplete(response)`        | 整个 Agent 循环全部结束、最终响应完成时 | 将最终完整的回答归档进历史消息列表，重置临时输入流状态。     |

---

#### 3. 为什么设计为可选参数？

将它设为可选，实现了 **UI 与 Agent 核心解耦（Headless 架构）**：
1. **带 UI 运行**：启动完整的终端应用（`pnpm dev`）时，`App.tsx` 会传入这些 callbacks，呈现漂亮的交互界面。
2. **无头模式 / 测试模式**：在单元测试、跑评测（`evals/`）、或者像你当前文件底部写的本地简单自测 `runAgent("你好，你在吗？")` 时，**完全不需要传 callbacks**，直接在控制台执行即可。

## 核心要点

1. **智能体 = LLM + 动作 + 循环**：由模型自主决策并持续执行，直到完成任务。
2. **由 LLM 控制执行流程**：它不只是被动响应，而是整个流程的主导者。
3. **智能体擅长重复性知识工作**：但不擅长需求模糊或高风险的任务。
4. **从简入手**：基础的 LLM 调用是起点，我们将在此基础上逐步扩展能力。

## 课后练习

1. **运行智能体**：向它发送一条消息，观察输出结果。
2. **更换模型**：尝试切换不同的模型，对比它们的输出效果。
3. **修改系统提示词（system prompt）**：观察提示词的调整如何改变智能体的行为。

## 课中笔记

**构建一个 agent 的艺术并不难，但让一个 agent 变好、变强大的难度是无限大**。

1. 在使用大语言模型（LLMs）时，`generateText` 函数的目的是什么？

   `generateText` 函数用于从语言模型生成文本响应。你向它提供模型、提示词（用户消息）以及可选的系统提示词，它会根据这些输入返回生成的文本。

2. 在大语言模型（LLMs）的语境中，什么是系统提示词（system prompt）？

   系统提示词是给大语言模型的基础指令，它为大语言模型预设了背景和指令。例如，它可能包含这样的指令：“你是一个有用的AI系统。你提供清晰、准确且简洁的回复。”这为LLM应如何响应用户查询设定了上下文和行为方式。

3. AI SDK 的提供商适配器模块（如 `@ai-sdk/openai`）的目的是什么？

   提供商适配器模块允许你在使用相同的 SDK 接口时，切换不同的模型提供商（如 OpenAI、Anthropic 等）。这提供了极大的灵活性，让你无需重写代码即可更换大语言模型（LLM）提供商。

4. 在最基础的层面上，大语言模型（LLMs）工作原理的核心概念是什么？

   从本质上讲，大语言模型（LLM）其实很简单：你给它一些文本（输入），它就会生成一些文本（输出）作为响应。其复杂性在于构建复杂的智能体（agents），这些智能体能够进行对话、执行任务，并持续产生良好的结果。
