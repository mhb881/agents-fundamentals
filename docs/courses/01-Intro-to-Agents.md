# 智能体（Agent）入门

## 概述

本节课程将带你认识 **AI 智能体（AI Agent）**——它们是什么、为何重要，以及它们擅长与不擅长的场景。此外，我们还将动手搭建第一个基础智能体。

## 什么是智能体？

每个人对智能体都有不同的定义，我的定义是：

**智能体是一个能够在循环中持续执行动作，直到完成任务的大语言模型（Large Language Model，LLM）。**

就是这么简单。它包含三个核心要素：

1. **LLM**：具备推理和决策能力的语言模型。
2. **动作（Actions）**：实际执行操作的能力（如调用工具、写入文件、发起 API 调用等）。
3. **循环（Loop）**：持续运转直至任务完成，而非只返回一次响应。

聊天机器人（chatbot）只回复一次，而智能体会持续工作。

### 你可能听过的其他定义

* **“配备了工具的 LLM”**——过于简单。仅仅拥有工具并不足以构成智能体。
* **“能够自主达成目标的 AI”**——过于宽泛。究竟什么才算“自主”？
* **“能够规划并执行的 AI”**——比较接近了，但简单的智能体并不一定需要规划能力。
* **“由 LLM 控制执行流程的系统”**——这个定义很准确，核心在于由 LLM 决定下一步该做什么。

这些定义的共同点在于：**LLM 处于主导地位（in the driver's seat）**，由它来决定采取什么行动以及何时停止。

## 为什么需要智能体？

单纯的 LLM 存在以下局限：

* 知识局限于训练数据（信息过时且不完整）
* 仅支持单轮响应（缺乏状态持久性）
* 只能生成文本（无法对现实世界产生实际影响）

而智能体能够：

* 获取实时数据（通过 API、数据库、互联网）
* 逐步拆解并处理多步骤复杂问题
* 真正“动手做事”（创建文件、发送邮件、部署代码）
* 从错误中恢复，并尝试不同的解决路径

两者的本质区别在于**自主行动能力（agency）**——不仅能描述世界，更能作用于世界。

## 智能体擅长什么？

1. **重复性知识工作**：信息检索、内容摘要、数据录入。
2. **代码生成与修改**：编写代码、调试（debug）、重构。
3. **多步骤工作流**：需要按顺序组合调用多个工具的任务。
4. **探索性任务**：例如“在这个代码库（codebase）中找出所有的 X，然后执行 Y”。
5. **辅助性任务**：提升人类工作效率，而非取代人类。

## 智能体不擅长什么？

1. **需要物理实体参与的任务**：这一点显而易见。
2. **缺乏人工监督的高风险决策**：不要让智能体去审批贷款或解雇员工。
3. **依赖人类审美品味的创意工作**：智能体可以起草初稿，但最终拍板的应该是人。
4. **成功标准模糊的任务**：比如只说一句“把这个改得更好”，却没有任何具体要求。
5. **实时性或对延迟敏感的操作**：LLM 的调用耗时较长。
6. **需要真正逻辑推理的任务**：LLM 的**本质是模式匹配而非真正的推理**，面对复杂逻辑往往会失效。

智能体最危险的失效模式是：**一本正经地把事情做错**——因为它们并不知道自己不知道什么。

## 智能体循环

每个智能体都遵循相同的基本运行模式：

```
1. 接收任务
2. 思考下一步该做什么
3. 执行动作（或直接回复）
4. 观察执行结果
5. 若任务尚未完成，返回第 2 步
```

这种模式通常被称为 **ReAct 模式（Reason + Act，推理与行动）**：模型先推理该做什么，接着采取行动，然后再基于观察到的结果进行新一轮推理。

## 智能体的未来趋势

未来的演进方向包括：

* **更强的工具使用能力**：模型在准确选择和调用工具方面的表现正大幅提升。
* **更长的上下文（context）**：更大的记忆容量意味着能够处理更复杂的任务。
* **多智能体系统（Multi-agent systems）**：多个智能体之间相互协同配合。
* **垂直领域专用智能体**：针对特定领域（如编程、科研等）进行微调的智能体。
* **更完善的安全护栏（guardrails）**：让智能体更加安全可控，清楚自身的能力边界。

发展趋势非常明确：智能体将在更少人工干预的情况下处理越来越复杂的任务。但我们尚未达到那个阶段——**当下的智能体仍然需要人类监督**。

## 代码

### src/agent/run.ts

创建基础的智能体运行器（runner）：

```typescript
import { generateText, type ModelMessage } from "ai";
import { openai } from "@ai-sdk/openai";

import { SYSTEM_PROMPT } from "./system/prompt.ts";

import type { AgentCallbacks } from "../types.ts";

const MODEL_NAME = "gpt-5-mini";

export async function runAgent(
  userMessage: string,
  conversationHistory: ModelMessage[],
  callbacks: AgentCallbacks,
): Promise<any> {
  const { text } = await generateText({
    model: openai(MODEL_NAME),
    prompt: userMessage,
    system: SYSTEM_PROMPT,
  });

  console.log(text);
}
```

这是最简化的“智能体”——本质上只是一次普通的 LLM 调用。它还算不上真正的智能体，原因如下：

* **没有工具**（无法执行动作）
* **没有循环**（回复一次即停止）
* **没有记忆**（未使用对话历史记录）

我们将在后续课程中逐步加入这些能力。

## 核心要点

1. **智能体 = LLM + 动作 + 循环**：由模型自主决策并持续执行，直到完成任务。
2. **由 LLM 控制执行流程**：它不只是被动响应，而是整个流程的主导者。
3. **智能体擅长重复性知识工作**：但不擅长需求模糊或高风险的任务。
4. **从简入手**：基础的 LLM 调用是起点，我们将在此基础上逐步扩展能力。

## 课后练习

1. **运行智能体**：向它发送一条消息，观察输出结果。
2. **更换模型**：尝试切换不同的模型，对比它们的输出效果。
3. **修改系统提示词（system prompt）**：观察提示词的调整如何改变智能体的行为。

### 译注与代码说明

1. **术语选择**：
* **Agent**：中文技术圈常译为“智能体”，也有大量工程实践文档直接保留英文 `Agent`；为保持行文连贯，本译文统一采用**智能体**。
* **context**：结合后文“More memory means more complex tasks”，此处指模型的**上下文（窗口/记忆容量）**，而非一般编程语境中的“执行上下文”。


2. **原文代码可能存在的问题**：
* **缺少返回值**：`runAgent` 的返回类型签名为 `Promise<any>`，但函数体内部仅执行了 `console.log(text)`，未写 `return` 语句（实际返回 `Promise<void>`）。
* **未使用的函数参数**：`conversationHistory` 和 `callbacks` 已在参数列表中声明，但函数体内部均未使用（作者在正文中提到当前版本暂未使用对话历史，推测这两个参数是为后续课程预留的接口签名；若项目开启了严格的 TypeScript 静态检查，可能会触发未使用变量告警）。
* **显式 `.ts` 导入后缀**：`"./system/prompt.ts"` 和 `"../types.ts"` 直接带有 `.ts` 扩展名，在标准 `tsc` 编译环境下需要开启 `allowImportingTsExtensions` 选项才能通过校验（在 Bun、Deno 或现代构建工具中可正常运行）。
