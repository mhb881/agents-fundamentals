这个错误是 **401 Unauthorized（认证失败）**，来自 DeepSeek API 网关。

---

### 1. 错误原因解析

报错信息：
```text
Authentication Fails (auth header format should be Bearer sk-...)
```

在调用 DeepSeek 接口时，HTTP 请求头的认证格式必须为 `Authorization: Bearer sk-xxxxxx`。当 DeepSeek 网关收到**空的 API Key** 或**未包含有效 Key** 的请求头时，就会返回这个确切的错误提示。

结合你的代码分析：

在 [providers.ts](file:///d:/WorkSpace/大师课/ai-courses/作者-Scott-Moss/agents-v2/src/agent/providers.ts#L4-L6) 中：
```typescript
export const deepSeek = createDeepSeek({
  apiKey: process.env.DEEPSEEK_API_KEY ?? "",
});
```
当 `process.env.DEEPSEEK_API_KEY` 读取不到（值为 `undefined`）时，代码降级使用了 `""`（空字符串）。SDK 最终发出了 `Authorization: Bearer `，因此被 DeepSeek 直接拒绝。

---

### 2. 为什么 `DEEPSEEK_API_KEY` 会读取不到？

通常是以下几种情况之一：

1. **终端执行目录（cwd）不在项目根目录（最常见）**：
   - `dotenv` 默认只在**当前终端所在的路径（`process.cwd()`）**寻找 `.env` 文件。
   - 如果你在终端里 `cd src/agent` 后再运行脚本，`dotenv` 会去 `src/agent/.env` 查找，导致找不到根目录的 `.env`。
2. **运行脚本时 `.env` 尚未保存**：
   - 编辑了 [.env](file:///d:/WorkSpace/大师课/ai-courses/作者-Scott-Moss/agents-v2/.env) 但当时处于未保存状态（编辑器标签上有未保存圆点）。
3. **未通过 package.json 的启动参数注入环境变量**：
   - 项目的 [package.json](file:///d:/WorkSpace/大师课/ai-courses/作者-Scott-Moss/agents-v2/package.json#L13-L14) 中是通过 `tsx --env-file=.env` 注入环境的，如果直接用 `tsx` 单独跑某个子文件而没经过根目录加载，可能丢失变量。

---

### 3. 解决与优化建议

#### ① 确保在项目根目录运行
确保终端在项目根目录下（`agents-v2`），执行：
```bash
pnpm exec tsx src/agent/run.ts
```

#### ② 在代码中加入防呆校验，避免静默 fallback 为 `""`
建议修改 [providers.ts](file:///d:/WorkSpace/大师课/ai-courses/作者-Scott-Moss/agents-v2/src/agent/providers.ts)，当环境变量缺失时尽早抛出清晰的错误提示，而不是发空请求：

```typescript
import "dotenv/config";
import { createDeepSeek } from "@ai-sdk/deepseek";

const apiKey = process.env.DEEPSEEK_API_KEY;
if (!apiKey) {
  throw new Error("环境变量 DEEPSEEK_API_KEY 未找到，请检查项目根目录的 .env 文件！");
}

export const deepSeek = createDeepSeek({
  apiKey,
});
```
